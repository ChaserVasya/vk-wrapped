# Требования к приложению

## Бизнес-требования

Приложение является аналогом Spotify Wrapped

Основные пожелания к тому, какие проблемы должно решить приложение:

- выделить любимые треки
- выводить статистику в различных разрезах, аналогично Spotify Wrapper

А также:

- плейлисты и альбомы разграничить по статистике,
- Иметь возможность настраивать различные параметры.

## Функциональные требования

- У пользователя должна быть возможность поделиться в виде json файла любыми данными.
- Юзер должен иметь возможность максимально сконфигурировать все параметры приложения, участвующие в логике
- Каждый функционал - отдельная страница. Разделять по смыслу и согласно UX.
- Если закрыть страницу VK, статус сохраняется ещё какое-то время, хотя юзер уже не слушает музыку. Следует это учитывать в логике и продумать этот момент.
- У юзера должна быть возможность обновлять токен

## Технические требования

- Приложение должно работать на android. Другие платформы сейчас поддерживать не надо.
- domain логика должна быть наиболее продумана и покрыта тестами, которые покрывают все возможные состояния входных данных.
- на бэке хранятся только сессии. Подробные данные надо получать с помощью vk api из приложения.
- полученные данные следует кешировать. Например, в sql-бд. И запрашивать только то, чего не хватает в кэше.
  - Согласно функциональным требованиям, должна быть возможность сбросить кэш
- У приложения должна быть ночная и дневная тема
- Сессия трэка, которую мы получаем с бэка, на самом является результатом поллинга. Соответственно, имеет погрешности.
  - Возможно, более реалистично трактовать сессию поможет её длительность, которую можно получить с помощью vk api
- Должны учитываться все состояния: загрузка, ошибка, наличие данных
- Всё должно соответствовать всем best practices и принципам программирования

Любые улучшения UI, UX, DX и прочего - одобряются.
